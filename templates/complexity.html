3. Algorithmic Trade-offs, Scalability & Optimality

Algorithm Optimality Guarantee Advantages Limitations Scalability
0/1 Knapsack (DP) Always finds exact optimal profit. Avoids recomputing overlapping subproblems by caching in 2D table. Pseudo-polynomial: memory & runtime scale with numeric capacity $W$. Excellent for reasonable integer capacities; inefficient if $W$ is exponential.
Job Sequencing (Greedy) Guaranteed optimal for single-processor unit-duration jobs. Extremely fast, low memory overhead, straightforward implementation. Greedy choice fails if jobs have arbitrary durations or precedence constraints. Highly scalable; can process tens of thousands of jobs in milliseconds.
TSP (Backtracking + Pruning) Guaranteed absolute minimum cost tour. Prunes massive sub-trees early whenever partial cost $\ge best\_cost$. Factorial worst-case growth: exponential barrier remains for large $n$. Effective for $n \le 15$; requires heuristics/meta-heuristics (e.g. Genetic, Ant Colony) for large $n$.

4. Theoretical Complexity Classes Explained

Class P (Polynomial Time Solvable)

Definition: The set of all decision problems that can be solved by a Deterministic Turing Machine in polynomial time $O(n^k)$, where $k$ is a constant.

Example in System: Job Sequencing with Deadlines is solvable in $O(n \log n + nD)$, which is polynomial with respect to input parameters, placing it squarely in Class P.

Class NP (Nondeterministic Polynomial Time Verifiable)

Definition: The set of all decision problems for which a candidate certificate/solution can be verified by a Deterministic Turing Machine in polynomial time.

Key Insight: Verifying a given answer is much easier than discovering the optimal answer from scratch.

NP-Hard (At Least as Hard as Any NP Problem)

Definition: A problem $H$ is NP-Hard if every problem $L \in \text{NP}$ can be polynomial-time many-one reduced to $H$ ($L \le_P H$). NP-Hard problems do not need to be decision problems or belong to NP.

Example in System: TSP Optimization ("Find the absolute shortest tour") and 0/1 Knapsack Optimization ("Find subset with maximum profit") are NP-Hard.

NP-Complete (The Hardest Problems in NP)

Definition: A decision problem $C$ is NP-Complete if:

  1. $C \in \text{NP}$ (verifiable in polynomial time), AND
  2. $C \text{ is NP-Hard}$ (every problem in NP reduces to $C$ in polynomial time).

5. Optimization vs. Decision Problem Distinction

TSP Case Study

Optimization Problem: "Find the tour that achieves the minimum possible total travel distance."
→ Output is a route & numeric cost. Classified as NP-Hard.

Decision Problem: "Given distance matrix and budget $K$, does there exist a tour with total distance $\le K$?"
→ Output is YES/NO. Verifiable in $O(n)$ time. Classified as NP-Complete.

0/1 Knapsack Case Study

Pseudo-Polynomial Time: Although the DP algorithm has runtime $O(nW)$, $W$ represents the numeric capacity, whose binary encoding size is $k = \log_2 W$.

Since $W = 2^k$, runtime is actually exponential in the input bit-length ($O(n \cdot 2^k)$). Thus, 0/1 Knapsack is pseudo-polynomial, weakly NP-Complete (decision), and NP-Hard (optimization).
